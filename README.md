# Agent Assurance Atlas

**Excel tools for assessing LLM systems and planning controlled SOC autonomy.**

Use the security assessment to decide whether an AI integration has the controls and evidence needed for a pilot or production review. Use the autonomy map to decide which SOC actions can be released at which level of automation under your policy, evidence and readiness constraints.

**Release: `0.1.0-review.1` — reviewed prerelease.** The original workbooks are preserved unchanged. The review found a SOC confidence-configuration defect, eight stale LLM comparator caches, and two reporting limitations. The default SOC confidence order and the tested central approval and release gates behaved as documented. Read [known issues](docs/known-issues.md) before using or customizing the files.

## Choose a workbook

| Your task | Workbook | Starting point |
| --- | --- | --- |
| Assess an LLM or agent integration, compare candidate models, or review MCP components | [LLM_Agent_Security_Assessment_v0_6_8_r4.xlsx](workbooks/LLM_Agent_Security_Assessment_v0_6_8_r4.xlsx) | Blank assessment; begin with `README & Logic`, then `Scoping`. |
| Plan autonomy for security operations actions | [SOC-Autonomy-Map-v1.4.3.xlsx](workbooks/SOC-Autonomy-Map-v1.4.3.xlsx) | Twenty illustrative use cases; begin with `Guide`, `Scales` and `Autonomy map`. Replace the examples with local evidence. |

The tools complement each other, but do not exchange data automatically. Use the same use-case identifier and version in both, and keep their scores separate. An assessment recommendation does not replace a signed deployment decision; a SOC release candidate does not replace formal operational authorization.

## Start here

1. Save a working copy of the appropriate workbook and read its first guide sheet.
2. For the LLM assessment, complete the system header and all 19 scoping questions, answer applicable controls, attach evidence and finish each required MCP checklist. Recalculate before interpreting summaries.
3. For SOC, replace the example actions, ratings, current autonomy and readiness answers with your own assessment. Retain the shipped confidence adjustments `0, -1, -2` until the ordering defect is corrected.
4. Resolve incomplete inputs and review the decision or release explanations with the accountable owner. Record the decision and its supporting evidence.

The [quick start](docs/quickstart.md) explains both workflows. The [methodology](docs/methodology.md) explains scoring, gates, exclusions and the distinction between a target and a release candidate.

## Reproduce the checks

Python 3.10 or later is recommended. Run these commands from the repository root:

```sh
# Standard-library reference calculations; does not recalculate Excel formulas.
python tools/reference_checks.py > validation/reference-results.json

# Optional source-formula scenarios; reads files and keeps all changes in memory.
python -m pip install -r requirements-test.txt
python tools/scenario_eval.py --output validation/scenario-results.json
```

Both scripts accept `--workbook-dir /path/to/workbooks`. The scenario harness uses a purpose-limited interpreter; it is not a general Excel engine or native Excel automation. The [baseline crosscheck record](validation/interpreter-crosscheck.json) is a review artifact, not a crosscheck regenerated by these commands.
